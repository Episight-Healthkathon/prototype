### 0.4 Status → badge mapping (proposal; text + icon, never colour alone)

| `progress_status` | `outcome` | `stop_reason` | Badge text | Tone |
|---|---|---|---|---|
| `FLAGGED` | — | — | Flagged · not investigated | neutral |
| `INVESTIGATING` | — | — | Investigating · step *n* / *max* | info |
| `INVESTIGATION_FAILED` | — | any | Investigation failed — not a result | error |
| `BRIEF_READY` | `EVIDENCE_SUFFICIENT` | `SUFFICIENT_EVIDENCE` | Evidence sufficient for review | calm (do **not** use "legitimate" or green "pass") |
| `BRIEF_READY` | `EVIDENCE_CONFLICTING` | `CONFLICTING_EVIDENCE` | Conflicting evidence · human review | warning |
| `BRIEF_READY` | `EVIDENCE_UNAVAILABLE` | `REQUIRED_EVIDENCE_UNAVAILABLE` / `NO_ACTIONABLE_GAP` | Evidence unavailable · human review | warning |
| `BRIEF_READY` | `HUMAN_REVIEW_REQUIRED` | `EVIDENCE_PATHS_EXHAUSTED` | No explaining context found · risk unresolved | warning |
| `BRIEF_READY` | `HUMAN_REVIEW_REQUIRED` | `MAX_STEPS_REACHED` / `TOOL_FAILURE` / `TIMEOUT` | Stopped early (step limit / source failed / timeout) · human review | warning |

Every outcome still needs a human decision. The brief's `human_decision_notice` must be visible on the Brief screen.

### 0.5 Requirement (evidence-gap) states → UI wording

| State | Meaning | Suggested wording |
|---|---|---|
| `OPEN` | Not answered yet (may be partly read) | "Checking… (read X of Y documents)" |
| `FOUND` | Documented in the sources | "Documented" + evidence chips |
| `NOT_FOUND` | All readable sources read, nothing found | "Not found in available sources" (**not** "no") |
| `UNAVAILABLE` | Sources exist but cannot be read | "Cannot be assessed — documents unavailable" (**not** a negative finding) |
| `CONFLICTING` | Sources disagree | "Sources disagree" + both sides side by side |
| `FAILED` | A tool failed after retry | "Check failed — not assessed" |
| `SKIPPED` | Optional question not checked | "Not checked (optional)" + reason |

### 0.6 API errors → UI behaviour

| HTTP / `error.code` | When | UI |
|---|---|---|
| 404 `CASE_NOT_FOUND` / `EVIDENCE_NOT_FOUND` | Bad ID | Not-found state with a link back to the queue |
| 404 `RUN_NOT_FOUND` | No investigation yet | Show "Run Investigation" |
| 409 `INVESTIGATION_IN_PROGRESS` | Start pressed while running | Switch to polling the existing run (`details.run_id`) |
| 409 `INVESTIGATION_ALREADY_COMPLETED` | Start pressed after a finished run | Open the existing result; offer "Re-run" (`{"rerun": true}`) |
| 409 `BRIEF_NOT_READY` | Brief before completion | Show progress or "Run Investigation" |
| 422 `VALIDATION_ERROR` | Bad query | Developer error; show message |
| 503 `SERVICE_UNAVAILABLE` | Database down | Backend-unavailable banner; never show stale data as current |

Every error has `error.request_id` (same as the `X-Request-ID` header). Show it in error states for debugging.
